# Offline data, alignment, and evaluation

`frc_world_model/data.py` and `frc_world_model/evaluation.py` use the Python standard library. They read supplied local JSONL files, prepare deterministic windows, and score forecasts. They never start a simulator, connect to a robot, download weights, allocate cloud resources, or train a policy. No authorized real robot logs were supplied for this implementation. Synthetic fixtures and bounded learning runs establish plumbing only.

The local schema version is `frc-world-model-local-log-v1-pending-binding`. It remains a private offline envelope, not a production World-State contract or NetworkTables topic. The exact exported `frc-prediction/1` request/reply schemas and golden vectors are now pinned and consumed in `bindings.py`. `converter.py` converts only the six ego features and three robot-relative accepted chassis commands that v1 actually provides; eight-state mechanism records remain synthetic/local until the contract supplies those missing states. Full raw wire envelopes, request/candidate/model/snapshot identities, expiry, source/mapping revisions and metadata hashes are retained in the conversion report and per-record request provenance. See `BINDINGS.md` for the exact boundary and prerequisites.

A state layout explicitly lists ordered feature names, units, and angle indices. Angle units must be `rad`. An action layout separately declares ordered command features. The initial synthetic layout has field-frame position and heading, robot-relative chassis velocity, mechanism position/velocity, and four actions: robot-relative accepted chassis `vx`, `vy`, `omega`, and a mechanism setpoint. These dimensions are provisional until matched to World-State. An untimed waypoint or goal is not a physical action. A controller-owned adapter must produce the same timestamped expected command sequence used for training.

Every local record has these prerequisites:

- `schema_version`, a nonempty `record_id`, `kind` (`state` or `action`), nonempty `session_id`, and ISO date `day`.
- `identity` with nonempty string `robot_id`, `map_id`, `frame_id`, `calibration_id`, `source_id`, `source_epoch`, `reset_epoch`, `geometry_revision`, `localization_revision`, `configuration_revision`, `sync_mapping_revision` and `clock_domain`.
- `time_sync_valid: true`, integer `time_sync_error_ns <= time_sync_limit_ns`, exact `layout_hash`, ordered `values`, and an equally sized boolean `valid` vector. Synchronization bounds are retained in normalized records.
- States: nonnegative integer `state_time_ns`, `capture_time_ns <= state_time_ns`, causal-input provenance, and explicit `label_provenance`.
- Actions: `accepted: true`, nonnegative integer `accepted_time_ns`, and exclusive `interval_end_ns > accepted_time_ns`. Optional `execution` preserves clipping, saturation, requested/applied command differences, and their available evidence.

`layout_hash` is `canonical_hash(dataclasses.asdict(layout))`: SHA-256 of UTF-8 JSON with sorted keys and compact separators. Timestamps are declared synchronized source/state times; arrival order is never used to align actions and labels. The upstream exporter must verify clocks and sync uncertainty before asserting validity. State label provenance distinguishes measured values, fused estimates, independent ground truth, and synthetic fixtures. Fused estimates are not independently measured ground truth. `future_smoothed` states cannot be used as causal inputs.

An invalid feature is retained as `None`, even if a numeric placeholder appeared in the input. A valid feature requires a finite numeric value. Unknown values never become zero-valued labels. The strict window builder requires all selected state/action/target features to be valid. It excludes incomplete windows rather than introducing an unrecorded masked-loss change. Pickup labels and statistics are not produced without real labeled outcomes.

Original files are read-only. `load_jsonl(path, state_layout, action_layout)` returns `IngestionReport`, including the original resolved path, SHA-256, byte/line counts, semantic dataset hash, layout hash, label provenance counts, exclusions, and detections. Files remain byte-identical. Blank or malformed records are counted as exclusions. Exact duplicate records collapse deterministically; conflicting IDs and conflicting same-time values are rejected, including the original conflicting record. Out-of-order arrivals are reported, then valid records are sorted by causal timestamp. Overlapping applied-command intervals are rejected rather than guessed or averaged.

`split_sessions(report_or_records, SplitConfig(...))` splits complete days by default, before constructing windows. Sessions spanning midnight connect their days so that neither the session nor a connected day can leak across splits. `group_by="session"` is an explicit alternative. Groups sort by a seeded SHA-256 key and use deterministic largest-remainder allocation across `train`, `validation`, `calibration`, and `test`; ratios must sum to one. Small datasets may leave splits empty, which must be reported rather than relabeled as held-out evidence.

`build_windows(records, WindowConfig(timestep_ns, history_steps, horizon_steps, max_state_age_ns=0, max_action_age_ns=None))` constructs fixed-step windows within one episode identity. A reset/source epoch, robot, calibration, frame, map, source identity, or day boundary cannot share a window or recurrent carry. Grid timestamps align to the declared timestep. At time `t`, a state can only come from the most recent state timestamp `<= t`; it must be within the explicitly configured age tolerance, which is less than one timestep. No future-state interpolation occurs. Zero age tolerance requires exact grid samples. The manifest records gap detections and excluded alignment windows.

For a window ending its observed history at `t`, history contains states through `t`; `history_actions` contains commands for the preceding history intervals; `actions` contains commands for `[t,t+dt)`, `[t+dt,t+2dt)`, and subsequent forecast intervals; targets contain the later state labels. Commands must cover the entire interval. A mid-step command transition or command gap excludes the window; mode/setpoint averaging is not invented. Optional action-age limits reject stale commands even when a logged interval claims coverage. Source timestamps and original selected record IDs remain available in each `Window`. Targets may be causally resampled within the explicit tolerance, and that timing tolerance is part of the experiment configuration.

`prepare_offline(report, state_layout, action_layout, window_config, split_config)` returns the splits, per-split `WindowReport` objects, and separate state/action normalizers. It does not train. `ReversibleNormalizer.fit(values, layout, split="train")` rejects other fit splits. It fits each raw train record once rather than overweighting records duplicated by sliding windows. Finite known values supply each feature's mean and population standard deviation; scale has a positive minimum. Angles use the train-only circular mean and wrapped angular differences. An ambiguous circular mean fails explicitly. Transform/inverse preserve unknown values and wrap angles into `[-pi, pi)`. The metadata records the training-values hash, fit count, centers, scales, layout, and the named external preprocessing change. Angle wrapping has a discontinuity at the chosen branch; changing to a sine/cosine representation would change model dimensions and must be recorded as a method change.

`evaluate_windows` gives a predictor only `PredictorInput`: causal history vectors, their interval commands, future expected commands, cutoff, fixed timestep, episode key, and window ID. Future labels are deliberately absent. Each callback must perform its multistep rollout without future-state teacher forcing. One-step scoring uses only the first horizon. Open-loop scoring uses each independent rollout's subsequent horizons. Refreshed forecasts restart from the observed cutoff of each successive window; they are labeled separately even when their recorded-window scores coincide with the same open-loop rollouts.

Persistence holds the last state. Constant velocity analytically integrates a constant robot-relative body twist and wraps heading; mechanisms hold. `AnalyticalConfig` supplies explicit ego/command indices, positive chassis response constants, optional clipping limits, and optional first-order mechanism setpoint responses. Its constants require real calibration; synthetic defaults are not robot calibration. Integration uses interval-average response velocity and average angular velocity, an explicit approximation for coupled accelerating motion. Mechanism modes, interlocks, stopping limits, or accepted tolerances cannot be inferred from continuous setpoints alone.

All methods must use identical splits, windows, and horizons. Reports contain per-feature and per-horizon MAE, RMSE, p50, p95, p99, maximum, position/heading/velocity errors, per-session distributions, provenance, and missing-prediction counts. Invalid predictor shapes, NaNs, or exceptions count as missing forecasts rather than successful zero-error predictions. The runtime owns the analytical fallback. Empirical label error, sensor error, stochastic sampling, and ensemble disagreement are distinct; these deterministic metrics are not physical covariance.

`ablate_inputs` supports explicitly named history/action ablations. A neutral action must be provided and documented; zero is not assumed to mean safe or physically neutral. A fixed-length model requires a documented fixed-length history ablation, as used by the evaluator orchestration. `calibrate_session_bounds` only accepts a calibration split label and computes descriptive quantiles of session maximum errors; callers must supply genuine held-out calibration results. The function makes no guaranteed coverage claim. Real footprint, stopping distance, command/state delay, and mechanism tolerances are required before deriving physical acceptance bounds. Bounds and abstention policy must be frozen before inspecting final-test results. No real calibration or physical tolerance evidence was supplied, so advisory status remains mandatory.

Example preparation, once a supplied config describes the local layouts and windows:

```sh
python tools/data_cli.py /absolute/authorized/log.jsonl \
  --config /absolute/experiment/config.json \
  --output artifacts/dataset-manifest.json
```

The output is created exclusively; existing files, including logs, cannot be overwritten. The manifest includes source/dataset/configuration hashes, exclusion reports, group assignments, windows, train-only normalization metadata, and baseline scores. Final-test metrics are deliberately omitted from preparation. Model-only bounded CPU orchestration is in `tools/train_offline.py`, with frozen package construction in `frc_world_model/training.py`; native architecture/loss provenance is documented separately. `tools/evaluate_offline.py` compares frozen model and baselines and requires a previously frozen policy file before scoring final test.

The focused tests cover deterministic hashes, duplicate conflicts, ordering, identity/epoch isolation, gaps, causal state age, full-interval commands, invalid sync/schema/frames, NaNs, unknown masks, day/session leakage, circular reversibility, analytical body-twist/response behavior, no-future-label callback boundaries, failure counts, explicit ablations, and exclusive CLI output. These checks use synthetic fixtures. Executed-action logs cannot demonstrate counterfactual candidate ranking or closed-loop safety. Replay and shadow remain advisory until real held-out, on-device, and shadow evidence plus explicit approval support promotion; actual robot-code integration is on hold.
